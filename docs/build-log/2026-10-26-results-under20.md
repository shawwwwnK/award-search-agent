## Owner invocation and objective

## Independent investigation/design critique

Applied design-lab for design comparison/critique, OpenAI Docs for official API
capabilities, requesting-code-review and verification-before-completion for execution.
Separate architect, input investigator, runtime investigator and quality advisor
reviewed current state/ADR/contracts/workbook and prior evidence. Two implementers
own the experimental decision packet and lean wire/harness in separate files.

Observed: original writer inputs are170–247k tokens, much of them repeated reason,
validation and identity detail. Prior packet changes only reduced complete-case
tokens4–5%, or increased them. JSON scaffolding is39–47% of saved output characters;
reasoning is68% of output tokens across31 parsed final generations. Parsing/checking
are small; source preparation and remote count add a few seconds. Actual runtime
immediate full replay additionally measured3.287s on one admitted artifact, outside
prior diagnostic wall timing. Do not relabel those older19.6s diagnostics as actual
runtime success.

Design: one composer receives all exact choices as a dedicated semantic decision
table, not full legacy validation prose. Exact money/date/cabin/booking/traveler
states and joins remain available; full canonical/explorer evidence remains local.
Small factual relationship groups expose relevant schedule/cabin/buffer contrasts
without ranking or selecting winners. Lean typed roles derive selections once and
expand to canonical source-resolved document blocks. Optional claim annotations
are intentionally absent in this profile; semantic review remains necessary.

Independent critique requires decision-field audits beyond alias preservation,
explicit unknown/support distinctions, exact role membership, no silent handling
of multiple benchmarks, stable repeated-reference semantics, and prospective
quality grading. None are permission gates for already-authorized execution.
